# Пошагово с нуля

Нужно: панель Remnawave, сервер с Python 3 (подойдёт тот, где стоит bridge-guard или ваш бот),
отдельный Telegram-бот для тревог. Сторожа только читают панель — сломать что-то им нечем.

## Что это и зачем

- **Нода** — сервер, которым управляет панель. **Мост** — нода в стране клиентов, через которую
  они выходят на остальные ноды. **Профиль** — конфиг xray, где записано, на какие ноды мост
  отдаёт трафик (балансир «Авто» и правила по режимам).
- **Сторож нод** раз в день смотрит на все ноды глазами, которых нет у панели: перегруз по ядрам,
  память, полоса и — главное — «нода в маршрутизации моста, но трафика нет» (так выглядит
  блокировка по IP, для панели такая нода здорова).
- **Сторож трафика** раз в 30 минут копит расход каждой ноды по сырым счётчикам интерфейса —
  так считает хостер — и предупреждает по прогнозу, а не когда уже поздно.

## Шаг 1. Токен панели

Панель → **API Tokens** → **Create** → имя `fleet-guards` → скопируйте (показывается один раз).

## Шаг 2. Бот в Telegram

@BotFather → `/newbot` → имя → username (кончается на `bot`) → скопируйте токен `123456789:AAF…`.
Не используйте бота магазина — он занят своей программой. Кому слать, сторожа определят сами:
мастер попросит открыть нового бота и нажать Start.

## Шаг 3. Одна команда

```bash
curl -fsSL https://raw.githubusercontent.com/ponoroshca/remnawave-fleet-guards/main/scripts/install.sh | sudo bash
```

Что спросит мастер и что вы увидите (адреса — для примера):

Про «объём по умолчанию»: если у нод в панели задан лимит трафика (Traffic limit) — сторож
возьмёт его, введите `0`. Если лимитов в панели нет, а хостер даёт, например, 32 ТБ на сервер —
введите `32`; для отдельных нод объём можно задать в конфиге (`traffic_guard.overrides`).

Про «как считает хостер»: у большинства — большее из направлений (`max`); если в тарифе
написано «суммарный трафик» — `sum`. Не уверены — оставьте `max` и сверьте с первым счётом.

## Шаг 4. Ёмкость канала (по желанию, но полезно)

Чтобы сторож ловил перегруз полосы, ему нужна ёмкость каждой ноды в Мбит. Замерьте
`probe-speed.sh` из [node-kit](https://github.com/ponoroshca/remnawave-node-kit) и запишите
в `/etc/fleet-guards/config.json`:

```json
"capacity_mbit": { "FI-1": 990, "NL-1": 450, "RF-1": 800 }
```

Важно: `probe-speed` печатает **запас** сверх текущих клиентов — записывайте запас + фон на
момент замера, иначе сторож покажет больше 100% канала.

## Шаг 5. Убедиться

```bash
fleet-guards doctor          # все ✅
node-guard --force           # отчёт по нодам в Telegram прямо сейчас
traffic-guard --report       # таблица трафика
```

Дальше сторож нод пишет раз в день только если что-то нашёл (отчёт «всё в норме» — по `--force`),
сторож трафика — при пересечении порога.

## Если что-то не так

| вы видите | что это значит | что сделать |
|---|---|---|
| `панель не ответила` / `токен не принят` | адрес без `https://` или обрезанный токен | проверьте адрес в браузере, токен скопируйте заново |
| в отчёте у нужной ноды нет `←в маршруте` | её нет в балансире/правилах выбранных профилей, или мост ходит на её второй IP | проверьте `bridge_profiles`; второй IP → `alt_ips` |
| сторож каждый день ругается на ноду, которую вы отставили сами | — | впишите её в `parked` с причиной — будет строка в отчёте вместо тревоги |
| `outbound моста смотрит на X — такого адреса нет ни у одной ноды` | опечатка в профиле или второй IP ноды | `alt_ips: {"X": "адрес ноды в панели"}` |
| трафик показывает 0 ТБ и 0% сразу после установки | учёт начался сейчас | это норма: копится с момента установки, прогноз честный через 3 дня |
| `Telegram НЕ отправился` | с сервера в РФ api.telegram.org недоступен | `telegram.proxy` в конфиге (HTTP-прокси) |
| `СТОП: … уже существует и это не наш юнит` | на сервере другая программа с именем node-guard | переименуйте её или ставьте на другой сервер |

## Приложение. Как зайти на сервер, если никогда не делали

Сервер — это компьютер у хостера, к нему подключаются по SSH из терминала. После оплаты
хостер присылает IP-адрес, логин (`root`) и пароль (или вы указали ssh-ключ).

**Windows 10/11:** откройте PowerShell (Пуск → напишите `powershell` → Enter) и введите:

```
ssh root@203.0.113.10
```

(вместо `203.0.113.10` — IP вашего сервера). При первом подключении спросит
`Are you sure you want to continue connecting?` — напишите `yes`. Потом пароль —
**при вводе он не отображается**, это нормально: вставьте и нажмите Enter.

**Mac / Linux:** то же самое в приложении «Терминал».

Вы внутри, когда видите приглашение вида `root@server:~#`. Теперь копируйте команду из
инструкции целиком и вставляйте: в PowerShell — правой кнопкой мыши, в Терминале Mac —
Cmd+V. Enter — выполнить. `sudo` в командах не мешает, даже если вы уже root.

Отключиться — `exit`. Если связь оборвалась посреди установки — просто зайдите снова и
запустите команду ещё раз: скрипты рассчитаны на повторный запуск.
